# ImageTool · M1 框架 + M2 裁剪/变换

纯前端（无依赖、无构建）的图片工具。中间区是一块 `<canvas>` 视口，支持缩放与平移；
文件读写走浏览器原生 API（有 File System Access 就原地保存，否则降级到下载）；
M2 起可以真正改动像素：矩形裁剪、90° 旋转、水平/垂直镜像。

## 运行

直接双击 `index.html` 即可使用（脚本是普通 `<script>`，没有 ES Module 的 CORS 限制）。

推荐用本地服务器打开，文件对话框体验更完整：

```powershell
python -m http.server 8000 --bind 127.0.0.1   # 或 npx serve -l 8000
```

然后访问 `http://127.0.0.1:8000/ImageTool/`（取决于你在哪个目录起服务）。

## 界面结构

```
 ┌─ 打开 · 保存 · 另存 │ 裁剪 · 旋转 ┆ 缩放 ┆ 调色 · 滤镜 ──── ● 文档名
 ├───────────────────────────────── 图片呈现区（canvas）───────────────┤
 │  滚轮缩放 · 拖动平移 · 棋盘透明底      ┌─────────────┐               │
 │  裁剪时：选区 / 手柄 / 三分线      ╱  │ 裁剪参数浮窗 │               │
 ├──────────────┬───────────────┬───┴───┴─────────────┴────────────────┤
 │ B1 尺寸信息  │ B2 光标坐标   │ B3 缩放 slider ％输入    │ 适应  1:1  │
 └──────────────┴───────────────┴─────────────────────────┴────────────┘
```

- **工具栏 1 文件** —— 打开 / 保存 / 另存为。
- **工具栏 2 裁剪 · 旋转** —— 已实现（M2）：`裁剪` 进入预备裁剪模式并浮出参数面板；
  `旋转` 显示/隐藏旋转与镜像面板。
- **工具栏 3 缩放**、**4 颜色** —— 有意保留的占位（虚线样式 + 禁用），
  点击空白处会给出对应里程碑提示。缩放能力目前由状态栏 **B3** 提供。
- 四个分组**不显示栏目标题**，只靠分组间的渐变细线划分；悬停看按钮 tooltip。
- **视觉**：浅底 + 深色工具栏的混搭。顶部一条深色磨砂玻璃条（`--tb-*` 一组变量），
  承载按钮与文档名；呈现区与状态栏是浅色的。页面底层是一层极淡的环境光晕与细颗粒，
  半透明表面浮在它上面做折射；强调色只用一枚克制的靛蓝（滑块进度、焦点环、
  当前文档名的小圆点）。文档名的小圆点在“有未保存改动”时变琥珀色。
- **浮窗**：裁剪 / 旋转面板是毛玻璃卡片，可拖动标题条挪位置，Esc 收起。

### M2 裁剪模式

先按 `C` 或点「裁剪」进入 **预备裁剪模式**：选区默认为整幅，此时**直接拖动就是
框选**（而不是把整幅搬走）；一旦选区变小时，拖动选区内部变成移动、拖 8 个手柄
变成只调该边。选区外压暗、内部显示三分构图线，右下角浮出参数面板。
改动像素只发生在按「实施裁剪」之后。

面板里两组输入互相换算，规则是「对侧不动」：

| 你改 | 结果 |
| --- | --- |
| 左 / 右 | 该边移动，另一边固定 → **宽**随之重算 |
| 上 / 下 | 该边移动，另一边固定 → **高**随之重算 |
| 宽 / 高 | 左上角不动，右下边让位 → **右 / 下**边距重算 |

所以四边距 `左+右+宽 = 图宽` 是不变量，任何时候两组数字都自洽。选区始终以
**整数图片像素**存储，因此缩放/平移后重新框选、微调、提交都精确不漂移；
超出图片范围的输入会被夹回来。

缩放范围 **1% – 1600%**，状态栏 slider 采用**对数映射**，并在 1/4、1/2、1×、2×…
等档位附近自动吸附，方便精确对齐 100%。

## 目录

```
ImageTool/
├── index.html              界面骨架（工具栏 / 呈现区 / 状态栏）
├── css/style.css           布局与主题
├── js/
│   ├── core/
│   │   ├── util.js         通用工具（clamp / 格式化 / rAF 合并调度）
│   │   ├── config.js       缩放常量、slider 对数映射、吸附、棋盘参数
│   │   ├── bus.js          模块间事件总线
│   │   └── state.js        单一数据源：doc / view / cursor
│   ├── modules/
│   │   ├── viewport.js     canvas 渲染与坐标变换 + overlay 挂载点
│   │   ├── statusbar.js    B1 尺寸 · B2 坐标 · B3 缩放控件
│   │   ├── toast.js        轻提示
│   │   ├── fileio.js       打开 / 保存 / 另存（API + 降级）
│   │   ├── crop.js         选区、手柄、压暗遮罩、预备裁剪模式
│   │   ├── transform.js    旋转 90° / 镜像（像素级重画，视图不跳）
│   │   ├── panels.js       裁剪浮窗 + 旋转浮窗（双向绑定）
│   │   ├── toolbar.js      顶部工具栏绑定、禁用态、模式按钟
│   │   └── input.js        鼠标 / 滚轮 / 键盘 / 拖放 / 粘贴
│   └── main.js             装配启动
└── test/smoke.js           无浏览器冒烟测试
```

状态与视图分离：`state.js` 是唯一数据源，`viewport.js` 只负责
`屏幕坐标 = 图片坐标 × scale + (x, y)` 的变换与绘制，交互集中在 `input.js`，
裁剪层通过 `viewport.onOverlay(draw)` 把选区画在同一块 canvas 上，面板模块
只订阅 `crop:rect` 一类事件写回输入框。模块之间靠 `bus.js` 的事件
（`doc:load` / `doc:meta` / `view:change` / `crop:enter` / `crop:rect` / `notify` …）
解耦，后面加调色、历史记录时可以照搬这套分层。

## 测试

```powershell
node test/smoke.js          # 90 项：加载 / HTML 契约 / 映射 / 几何 / 事件接线 / M2 编辑
```

测试用一个最小 DOM 替身在 Node 里跑完整个启动流程，并真的派发 `click`、
`wheel`、`pointerdown/move/up`、`keydown` 等事件，确认「按钮/快捷键/滚轮 → 视口
变换 → 状态栏文本」这条链路是一直通到底的（例如 `Ctrl+0` 是否真的改变了 scale、
B2 是否在指针出界时回落成 `—`）。M2 的部分额外守住了容易写坏的地方：边距⇄宽高的
换算不变量、拖空白处 vs 拖手柄 vs 拖选区的分支、越界夹取、单击不该把选区压成 1×1、
实施裁剪后视图的位移补偿、旋转后宽高交换而视觉中心不动。

## 实现要点与已知边界

- **透明底**：图片区域裁剪后用 canvas pattern 画棋盘，图案锚定到图片原点，
  平移时不闪动；`devicePixelRatio` 自适应，高分屏下不发虚。
- **保存的无损性**：没有改动过的文件仍然直接写回原始 Blob（PNG 不会因为解码再编码
  而退化）。一旦裁剪或旋转发生，`state.replaceImage()` 会作废原始字节并置 `dirty`，
  保存时自动转为 `canvas.toBlob` 重新编码 —— PNG 依然是无损的，JPEG 会重走一遍
  有损压缩（质量 0.95）。
- **坐标 B2**：`0 0` 是图片左上角，显示 1-based 像素序号，悬停 tooltip 给亚像素值；
  出界显示 `—`。
- **视图不打断**：实施裁剪会把屏幕位置平移 `-x·scale`，所以裁完看到的内容还是
  刚才那一块；旋转 90° 交换宽高，同时补偿 `±(w-h)·scale/2` 让视觉中心留在原处。
  两种操作都保留当前缩放比例，不会“编辑一下就跳回适应窗口”。
- **撤销**：还没做。M2 是一次性提交（实施裁剪 / 点旋转按钮即刻生效 + 标脏），
  取消只发生在提交之前（`Esc` / 取消裁剪 / 关面板）。历史记录排在 M5。
- File System Access API 只在安全上下文可用；不可用时“打开”退回
  `<input type=file>`，“保存”退回浏览器下载，此时没有原地写回的句柄。
- SVG/GIF 由 `Image` 解码为单帧，动图只会取当前帧。
